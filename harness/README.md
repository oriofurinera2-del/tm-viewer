# 制作ハーネス（役割分担とサブエージェント運用）

Claude Code と Codex（チャッピー）の両方で使う。役割の考え方は共通、モデル名だけ各ツールで違う。

## 指示の分担

| 用途 | 読むもの |
|---|---|
| 共通の仕様・現在地 | `docs/DESIGN.md`（とくに 7. バージョン計画 / 8. 未確認事項） |
| 共通の運用 | このファイル |
| Claude ⇄ Codex の割り振り・進捗・連絡 | `harness/HANDOFF.md` |
| Claude Code のみ | `CLAUDE.md`、`.claude/` |
| Codex のみ | `AGENTS.md`、`.codex/` |

共通仕様の変更は DESIGN.md に、運用の変更はこのファイルに記録する。

## 役割とモデル

初期運用の割り当て。品質や料金比を実測したものではない。

| 役割 | 担当する作業 | Claude Code | Codex |
|---|---|---|---|
| 親（メイン） | 相談、段取り、結果の統合、ブラウザでのサイト確認、確定済み内容の文書反映 | セッションのモデル | Terra / low |
| `code` | アプリのコード（main / preload / renderer / 解析処理 / ビルド設定）の作成・修正・テスト | opus | Terra / medium |
| `design-reviewer` | 複数機能にまたがる設計、UI 案の比較、セキュリティ設定のレビュー。**読み取り専用** | opus | Sol / medium |
| `script-runner` | `npm install` / ビルド / 既存テストの実行と結果報告 | haiku | Luna / low |
| `researcher` | Electron・electron-builder・ライブラリの仕様調査、公開情報の調査 | sonnet | Terra / low |

- 短いファイル読み取りのたびに子を作らない。
- 低いモデルが同じ原因で 2 回失敗したら、原因と再現条件を添えて一段上げる。黙って高いモデルに変えない。
- 上位モデル（design-reviewer）は担当範囲の判断だけ行い、実装は `code` に戻す。

## 開始ゲート

各作業の最初に:

1. 依頼を `相談 / 読み取り / 実装・修正 / ビルド・テスト実行 / 設計レビュー / 調査` に分類する。
2. 最初の返答で `担当: code (opus)` のように役割を示す。
3. 実装と設計判断が両方ある場合は、`design-reviewer` → ユーザー確認 → `code` の順に分ける。
4. 最終報告に、実際に使った役割を書く。

**親が直接やってよいこと**: 読み取り、限定検索、既存スクリプトの単純実行、確定済み内容の文書反映、委任結果の統合、ブラウザでのサイト確認。
**親が直接やらないこと**: まとまったコード編集、設計の結論。「短いから」は理由にならない（1〜2 行の自明な修正は例外）。

ただし、**方針が決まっていない実装は、役割に関係なく着手しない**（CLAUDE.md / AGENTS.md の「決める前に」）。

## サブエージェントへの依頼の書き方

依頼文に必ず入れる:

- 目的（1〜2 文）
- 担当ファイル（触ってよい範囲）
- 必要な前提（DESIGN.md の該当節番号。会話の全文は渡さない）
- 完了条件（何ができたら終わりか、どう確認するか）
- **「サブエージェント（Agent ツール）を起動しないこと」**
- **「最後にまとめてではなく、終わった分から順にファイルへ書くこと」**
- 報告形式: 結果・根拠・変更したファイル・未確認点を短く。全文の転記はしない

## 並列と消費の管理

- **同時に動かすのは最大 2 体。** 独立した作業のときだけ 2 体、通常は 1 体。
- Claude Code では Agent ツールの `model` を必ず指定する（上の表どおり）。指定しないと親と同じモデルで動き、消費が大きい。
- 並列を増やしすぎると、セッション全体の利用上限を数分で使い切り、ユーザーが作業できなくなる。過去に複数回起きている。
- 暴走や不要な子に気づいたら、報告するだけでなく実際に停止する（Claude Code では TaskStop）。
- 同じファイルの全文読み直し、同じ検索の繰り返し、親子で同じ調査をすることを避ける。

## このプロジェクト固有の注意

- **サイトの確認（ブラウザ操作）は親が行う。** ブラウザ操作のツールは親セッションにしかない。子には、確認済みの HTML 構造を文章かファイルで渡す。
- 解析処理のテストには、実際のページを保存した HTML を使う。ただし `test/fixtures/` に置く HTML からは、画像 URL・サムネイル・成人向けの本文を取り除いてからコミットする（CLAUDE.md の「リポジトリ内容」）。
- 動作確認のため実サイトに連続でアクセスするときも、DESIGN.md 4.4 の間隔を守る。
- ログインが必要な確認は、ユーザーに内蔵ブラウザで本人がログインしてもらってから行う。ID・パスワードを受け取ったり入力したりしない。
