# TM Viewer 設計書（ドラフト v0.1）

TOKYO Motion を PC で快適に見るための専用ブラウザ（Windows デスクトップアプリ）。

- 状態: ドラフト。`[要確認]` はログイン後の画面を見てから確定する。
- 最終更新: 2026-09-28

---

## 1. 目的

公式サイトに無い「フレンド・購読ユーザーの新着動画一覧」を中心に、閲覧の不便を解消する。

### 解決したい不満（サイト確認・ネット上の声より）

| 不満 | 出どころ | 対応 |
|---|---|---|
| フレンドの新着をまとめて見られない | 本人 / サイト確認（ユーザー単位の RSS なし） | 新着フィード |
| 勝手に別サイトへ飛ぶ・ポップアップ広告 | 知恵袋など多数 | 広告ドメイン遮断・ポップアップ禁止 |
| PRIVATE 動画が混ざって見られない | 知恵袋など | 「見られる動画だけ」切替 |
| 投稿日が「3 日 前」など相対表示のみ | サイト確認 | 動画IDで並べる（4.3） |
| どれを見たか分からない | 一般的な不満 | 視聴済みマーク |

### やらないこと

- 動画のダウンロード・保存機能
- 外部サーバー（すべて各自の PC 内で完結）
- ID・パスワードの保存や読み取り（**例外**: 4.1 の「ログイン情報の保存」を利用者が設定で有効にした場合のみ。2026-09-28 ユーザー決定）
- 投稿・コメント・フレンド申請などの書き込み操作の自動化（利用者がサイト表示の中で自分で行う操作は妨げない）

## 2. 利用者と配布

- 本人＋知り合い。Windows PC。
- 配布: GitHub（個人用の別アカウント・公開リポジトリ）の Releases に **ポータブル exe（zip）** を置く。
- 未署名のため初回起動で SmartScreen 警告が出る。README に「詳細情報 → 実行」の手順を書く。
- README・スクショにサムネイル等の成人向け画像を載せない。

## 3. 技術構成

| 項目 | 採用 | 理由 |
|---|---|---|
| アプリ基盤 | Electron | この PC に Node.js があり、追加インストール不要 |
| 画面 | 素の HTML/CSS/JS（フレームワークなし） | 小規模で保守しやすい |
| HTML 解析 | main プロセスで cheerio | サイトに API が無いため HTML を読む |
| 保存 | userData フォルダに JSON | DB 不要な規模 |
| ビルド | electron-builder（portable） | exe 1 つで配れる |

### プロセス構成

```
main プロセス
 ├─ セッション "persist:tm"（ログイン Cookie はここだけに保持）
 ├─ 取得キュー（1 件ずつ・間隔あり）→ cheerio で解析
 ├─ 広告ブロック（webRequest でドメイン遮断）
 └─ データ保存（JSON）
renderer（アプリ画面）
 └─ フィード・設定。Node 権限なし、preload 経由でのみ main と通信
サイト表示ビュー（ログイン／動画再生／サイト内の閲覧）
 └─ サイトのページをそのまま表示。外部ドメインへの遷移・window.open は拒否
```

セキュリティ設定: `contextIsolation: true` / `nodeIntegration: false` / `sandbox: true`。

## 4. 機能仕様

### 4.1 ログイン

- 初回起動でサイト表示ビューにログイン画面を出し、**利用者自身がサイト上で入力**する。
- アプリは入力欄を読まない。ログイン状態は Cookie として `persist:tm` セッションに残る。
- 自分のユーザー名を取得する方法: `[要確認]` ログイン後のヘッダー等から読む。
- ログアウト: 設定画面から Cookie を消去。

#### ログイン情報の保存（任意）

背景: サイトは「ログイン時の情報を記憶」にチェックしても、しばらくするとログアウトされる（ユーザー報告。サーバー側で切っていると推測、未確認）。Cookie を残すだけでは解決しない。

- 設定に「ログイン情報を保存して自動でログインする」。**初期値はオフ**。オンにするとき注意書きを出す: 「他人と共有している PC では使わない」「このサイト専用の（他で使い回していない）パスワードにする」。リスクは Chrome のパスワード保存と同程度（2026-09-28 ユーザーと合意）。
- ID・パスワードは **アプリの設定画面の入力欄** に利用者が入れる。サイトのページの入力欄は読まない。
- 保存は Electron の `safeStorage`（Windows の DPAPI。その PC のそのユーザーでしか復号できない）で暗号化し、ほかのデータとは別ファイルにする。`safeStorage` が使えない環境では、この設定自体を出さない。
- ログアウトされていたとき（取得でログイン状態が無い、またはサイト表示がログイン画面になった）に、サイト表示のログイン画面へ入力して送信する。**失敗したら 1 回で止め**、利用者に手動ログインを促す（連続失敗でアカウントが制限されるのを防ぐ）。
- パスワードはログ・画面・エラー文に出さない。送り先は `tokyomotion.net` のログイン画面だけ。
- 設定をオフにしたら保存した情報を消す。「保存した情報を削除」ボタンも置く。整理データの書き出し（4.8）には含めない。

### 4.2 新着フィード（中心機能）

取得の流れ:

1. 自分のフレンド一覧 `/user/<自分>/friends?page=N` を全ページ取得
2. 購読一覧 `/user/<自分>/subscriptions` を取得（含めるかは設定で切替）
3. 各ユーザーの `/user/<名前>/videos` **1 ページ目（18 件）** を取得
4. 全件をまとめ、動画IDの降順で並べて表示

表示する項目: サムネ・タイトル・投稿者・長さ・HD/PRIVATE・相対投稿日・NEW/視聴済み。

- **NEW**: 前回フィードを開いた時点で未取得だった動画。
- **見られる動画だけ**: 公開動画＋フレンドの PRIVATE 動画。フレンドでない購読ユーザーの PRIVATE は隠す。`[要確認]` フレンドなら本当に PRIVATE が見られるか。
- クリックでサイト表示ビューに再生ページを開き、視聴済みにする。
- 初期表示は全員分をまとめた「すべて」。左一覧で人を選ぶとその人だけに絞る。
- 表示は **100 件ずつ** で「次のページ」で続きを出す（個人の全動画・整理した動画も同じ）。フィードは取得済みのデータを分けて出すだけなので、ページ送りで追加の取得はしない。
- **非表示（ミュート）**: 左一覧の目アイコンで、その人を「すべて」から外す。絞り込みで開けばその人の動画は見える。
- サイトの公開新着はフィードに含めない（見たいときはサイト表示で閲覧する）。
- **サイトのタグ**: 一覧には無く、動画ごとに `/ajax/video_tag` で取る必要がある（8 章）。更新で見つかった NEW の動画だけ裏で順に取得し、それ以外はカードにマウスを乗せたときにその 1 本だけ取る。取ったタグは保存して取り直さない。カードに表示し、絞り込みにも使う。

#### 個人の全動画

- フィードの取得は各ユーザーの 1 ページ目だけ（1 人 1 回の取得）。
- 左一覧で人を選ぶと、その人の動画を **100 件ずつ** 表示し、「次のページ」で続きを表示する。
- 表示に足りない分だけサイトのページを取得する（サイトは 1 ページ 18 件 [実測] なので、100 件でおよそ 6 回・約 12 秒 [計算]）。取得間隔は 4.4 のとおり。
- 一度取得した古いページは保存し、次回は待たずに表示する。新しく増えた分だけ取り直す。
- 更新ボタンで全員の全ページを取りに行くことはしない（例: 100 人 × 10 ページ × 2 秒 ≒ 33 分 [計算]）。

### 4.3 並び順

- 投稿日は相対表示のみなので、**動画ID（URL の数字）が大きいほど新しい**とみなして並べる。
- `[要確認]` ID が投稿順に増えるか、複数ユーザーで確認する。
- 補助として「初めて取得した時刻」も保存する。

#### 投稿日の表示

- サイトには正確な投稿日が無い（一覧・動画ページとも「23 時 前」「398 日 前」のような相対表示のみ [実測]）。
- 「取得した時刻 − 相対表示」で推定し、カードには「2026/09/27 頃」と出す。1 日未満はおよそ 1 時間、それより古いものはおよそ 1 日の誤差。
- アプリが新着として初めて見つけた動画は「初めて取得した時刻」を優先して使う（こちらのほうが正確）。
- 相対表示（「23 時 前」）はマウスを乗せたときに出す。

### 4.4 サイトへの負荷対策

| 設定 | 初期値 [仮] |
|---|---|
| 取得の間隔 | 1 件ごとに 2 秒 |
| 同時取得数 | 1 |
| 再取得までの待ち（キャッシュ） | ユーザーごとに 30 分 |
| 自動更新 | なし（手動の「更新」ボタンのみ） |

エラー（429・5xx）が出たら、その回の取得を止めて表示する。

### 4.5 広告・勝手な移動の防止

- 既知の広告ドメイン（確認済み: juicyads / realsrv / magsrv など）への通信を遮断する。リストは JSON で差し替え可能にする。
- サイト表示ビューでは `tokyomotion.net` 以外への遷移と `window.open` を拒否する。

### 4.6 視聴済み

- 再生ページを開いた動画IDを記録する。一覧では薄く表示する。
- 設定から履歴を消せる。

### 4.7 アップロード

- アプリ独自のアップロード機能は作らない。サイト表示でサイトのアップロード画面を開き、利用者が操作する。
- サイトの画面は 1 回に 1 ファイルだけ選べる（8 章で確認済み）。複数あるときは 1 本ずつ上げる。アプリが順番に送信する仕組みは作らない（1 章「書き込み操作の自動化」に当たるため）。

### 4.8 独自の名前・タグ・得点

- 動画ごとに、自分だけの **名前**・**タグ**（複数）・**得点（★1〜5）** を付けられる。保存は自分の PC 内だけで、サイトには送らない。
- 入力場所は 2 か所（2026-09-28 ユーザー決定）:
  - サイト表示で動画を開いているとき、アプリ側の上部バー（ページの上に並べる。サイトのページには手を加えず、重ねもしない）。
  - フィードのカード: 普段は表示だけ。★はカード上で直接押して付ける。✎を押すとカードの下に小さな入力欄が開き、名前と独自タグを編集する。
- **独自タグとサイトのタグは別物**として扱う。独自タグ（例: 「1軍」「2軍」）は利用者が自由に付け外しでき、色付きで先に表示する。サイトのタグは読むだけで編集しない。絞り込みではどちらも選べる。
- フィードのカードの表示: サムネ（NEW / PRIVATE / HD / 長さ）、独自の名前（無ければ元のタイトル）＋元のタイトル小さく、投稿者のアイコンと名前、推定投稿日、★、サイトのタグ（1 行。あふれた分は「+n」、カーソルで全部表示・未取得ならその時取得）。
- 名前を付けた動画は、フィードでも元のタイトルの代わりに独自の名前を表示する（元のタイトルは小さく併記）。
- **整理した動画** 画面: 名前・タグ・得点のどれかを付けた動画の一覧。タグ・得点で絞り込み、得点順などで並べ替え。100 件ずつ表示。フィードから消えた古い動画もここから開ける。
- PC の入れ替え・故障に備え、書き出し・読み込み（JSON）を用意する。

## 5. 画面

アプリ独自の画面・設定・操作文言は日本語に統一する（2026-09-28 採用）。サイト表示に含まれるサイト自身の文言は変更しない。

| 画面 | 内容 |
|---|---|
| フィード | 上部: 更新ボタン・取得進捗・切替（見られる動画だけ / 購読を含める）。本体: サムネのグリッド |
| サイト表示 | サイトをそのまま表示する簡易ブラウザ（戻る/進む・広告遮断）。ログイン・再生のほか、新着の閲覧やフレンド申請などを利用者が手で行う。上部に「フィードへ戻る」 |
| 整理した動画 | 名前・タグ・得点を付けた動画の一覧（4.8） |
| 設定 | 取得間隔・キャッシュ時間・ログアウト・履歴消去・整理データの書き出し/読み込み・バージョン |

### フィード画面のレイアウト（採用: 2026-09-28）

モック: `docs/mock/feed.html` を正とする（下の図＋非表示の目アイコン＋100 件ずつのページ送り＋整理した動画／サイト表示の入力バー）。推定投稿日とサイトのタグの表示はモック未反映。

参考: YouTube「登録チャンネル」（サムネグリッド＋視聴済みバー）＋ 5ch 専ブラ（左にスレ一覧と未読数）。

```
┌──────────┬──────────────────────────────┐
│ すべて  (42) │ [更新] 取得中 12/30  ☑見られる動画だけ │
│ ─────── │ ┌────┐┌────┐┌────┐┌────┐     │
│ userA   (5)  │ │NEW ││NEW ││    ││視聴済││     │
│ userB   (3)  │ └────┘└────┘└────┘└────┘     │
│ ─購読─      │  タイトル / 投稿者 / 2:20 / 3日前   │
│ userD   (1)  │                                  │
└──────────┴──────────────────────────────┘
```

- 左: 「すべて」＋フレンド・購読者の一覧（未読数つき、未読のある人が上）。選ぶとその人だけに絞る。
- 右: 新着サムネグリッド。
- 懸念: フレンドが数百人だと左一覧が長い → 未読順の並び＋名前検索で対処。
- 他の候補: RSS リーダーの「まとめて既読」は取り入れる。TweetDeck 型（人ごとの列）は横に長くなるため不採用寄り。

## 6. 保存データ（userData/）

```
feed-cache.json   { "<ユーザー名>": { fetchedAt, allPagesFetchedAt, fetchedSitePages: [取得済みのサイトページ番号...], videos: [{ id, title, duration, hd, private, thumb, ago, postedAtEst, firstSeenAt, siteTags }] } }
state.json        { me, lastOpenedAt, watched: [id...], muted: [ユーザー名...] }
credentials.bin   safeStorage で暗号化した { id, password }（4.1 の設定がオンのときだけ存在）
notes.json        { "<動画ID>": { name, tags: [...], score, user, title, thumb, updatedAt } }
settings.json     { intervalMs, cacheMinutes, includeSubscriptions, viewableOnly }
blocklist.json    ["juicyads.com", ...]
```

個人の全動画の続きを取得するときは `fetchedSitePages` を参照する（2026-09-28 採用）。新しい動画が増えてページの境界がずれる場合も、動画IDで重複を除き、未取得の動画を飛ばさないようにする。

## 8. 未確認事項（実装前に確認）

2026-09-28 にログイン後の画面で確認した結果（画像は見ず、HTML の構造だけを読んだ）。

- [x] 自分のユーザー名: ヘッダーのドロップダウン（`a.dropdown-toggle`）と、メニュー内のリンク `/user/<自分>/videos` から取れる [実測]
- [x] フレンド一覧: `/user/<自分>/friends?page=N`、1 ページ 20 人 [実測]。各人は `div#friend_<数字>` の中の `a[href="/user/<名前>"]`。並び替え `?o=invite_date / recent_users / recent_logins / username` あり。**同じ枠に「削除」ボタンがあるので、取得処理はリンクを読むだけにし、ボタンには一切触れない**
- [x] 購読一覧: `/user/<自分>/subscriptions` [実測]。各人は `div#subscription_<数字>` の中の `a[href="/user/<名前>"]`（フレンド一覧と同じ形）。7 人でページ送りは無かった（多い場合のページ送りは未確認）。こちらにも「削除」ボタンがあるので触れない
- [x] 公式のまとめページ: `/feeds`（私のフィード）はあるが、購読している人の更新記録が少し並ぶだけで、フレンドの新着の代わりにならない（ユーザーの実感とも一致）。4.2 は予定どおり自前で作る。なお `/feeds` の日付は「01/18/26」のような絶対日付だった
- [x] フレンドの PRIVATE 動画: アプリ（C1 の土台）のサイト表示で、ユーザーが実際に再生できた（2026-09-28）[実測]
- [ ] 広告の配信元: 動画ページで外部への通信があったのは `jads.co`・`juicyads.com`・`realsrv.com`・`endowmentoverhangutmost.com`（ランダムな名前）・`addthis.com`、ほかに解析用の `google-analytics.com`・`googletagmanager.com` [実測]。動画の前の広告はプレイヤー（fluidplayer）の設定で `syndication.realsrv.com` から取る指定だったが、`realsrv.com` を遮断してもアプリ内で流れた（ユーザー報告）。アプリ内での実際の経路は未確認
- [~] 動画のタグ: 一覧にも動画ページの HTML にも入っていない。ページを開いたあと `POST /ajax/video_tag` で別に取得して表示している [実測]。確認に使ったブラウザがこの通信を止めていたため、送る内容と返ってくる形は未確認。**アプリの広告遮断で、サイト自身の `/ajax/…` や `/vsrc/…` を止めないこと**
- [~] 動画ID: 1 人分の一覧（18 件）で、上から下へ ID が小さくなっていた（新しい順に並んでいる）[実測・1 人のみ]。複数ユーザーでの確認は未実施
- [ ] 連続取得でアクセス制限されないか（間隔の初期値の妥当性）
- [x] 動画一覧: `/user/<名前>/videos?page=N`、1 ページ 18 件 [実測]。各動画は `div#video_<ID>`。PRIVATE は `.label-private`、長さは `.duration`、投稿日は `.video-added`（「23 時 前」のような相対表示）
- [x] アップロード画面（`/upload/video`）: ファイル選択は 1 つだけ（`multiple` なし）[実測]。サイトの画面では複数まとめて上げられない
- [x] 動画の総数: 一覧の上に「公開中 1 へ 18 の 686 ビデオ.」（686 件中 1〜18 件目）と出る [実測]。フレンド一覧・購読一覧にも同じ形の一文がある（「… の 61 友達.」「… の 7 subscriptions.」）。ページ送りにも最後のページ番号（例: 38）が出る。1 ページ目を読むだけで総件数と総ページ数が分かる。（最初の確認で「総数は出ていない」としたのは誤り。見出しだけを探していた）
- [x] サイトの検索: `/search?search_query=<語>&search_type=videos`。絞り込み `type=public|private`、期間 `t=t|w|m|a`、並べ替え `o=mr|mv|md|tr|tf|lg|bw` [実測]。1 語（japanese）は 35,030 件。英語 2 語（japanese amateur）は 2 回とも「ビデオが見つかりませんでした」が、日本語の 2 語（素人 カップル）は 1,426 件を返した [実測]。複数語検索をアプリで作り直さず、サイト検索をそのまま使う。「0 件と出て、読み込み直すと出る」症状は、当面は利用者が手で読み直す（自動読み直しは作らない、2026-09-28 ユーザー決定）。

## 9. リスク

- サイトの HTML が変わると取得が壊れる → 解析部分を 1 ファイルにまとめ、直しやすくする。
- サイト自体が閉鎖・移転する可能性がある（閉鎖を告知するタグや、閉鎖を求める署名活動を確認済み）→ 作り込みすぎない。
- 利用者が増えるほどサイトへのアクセスが増える → 4.4 の制限を緩めにできないよう、下限値を設ける。
